# METEO-6: Погода из ISM-датчиков по округе (rtl_433 внутри OpenWebRX+)

**Статус: Реализовано, развёрнуто на wakkanai (стек openwebrx: ism-exporter + weather-beacon)**

## Зачем

Собственный датчик (BME280 по USB-serial, METEO-1/3) умер 2026-11-13, а железо
(ESP32-плата) снято с хоста. Зато вокруг дачи в эфире на 433.92 МГц стабильно
слышны чужие ISM-датчики температуры/влажности — их OpenWebRX+ и так декодирует
встроенным rtl_433 (декодер ISM). Идея: вместо своего сенсора брать «окружающую
температуру по округе» — самое честное, что можно получить без железа.

## Конвейер

```
OpenWebRX+ (профиль 70cm активен всегда)
  └─ сервисный ISM-декодер (rtl_433, dial 433.920 из bands-r1 «LPD433»)
       └─ ISM-*.txt в temporary_directory (repr-строки dict на строку)
            └─ ism-exporter.py (tail + скользящее окно)
                 └─ meteo.prom (meteo_* + rtl433_*), textfile-коллектор
                      └─ aprs-beacon.py → R2BLN-13 в APRS-IS
```

## ism-exporter.py

Хвостит `ISM_DECODE_DIR` (`ISM-*.txt`), группирует декоды по `(model, id)`,
держит скользящее окно `ISM_WINDOW_S` (по умолчанию 1800 с). «Опорный» датчик —
с наибольшим числом декодов в окне (tie-break — свежесть): это автоматически
самый близкий/стабильный передатчик. Передатчик замолчал — его счётчик за окно
утекает, следующий занимает место без перезапуска. Пишет `meteo.prom` раз в
`ISM_INTERVAL_S` (5 с), атомарно (tmp + rename).

Формат строк в логе — `str(dict)` (repr с одинарными кавычками), не JSON:
`IsmParser` пишет `str(out)`, поэтому парсер пробует `json.loads`, затем
`ast.literal_eval`.

## Изменения aprs-beacon.py

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `APRS_TELEMETRY` | `1` | `0` — без T#-пакетов: погода только. Для wakkanai, где телеметрию хоста уже шлёт R2BLN-10 (METEO-5) |
| `APRS_SENSOR_NOTE` | `sensor-in-sun(temp+)` | подпись источника в комментарии к погоде. ISM-маячок ставит сюда rtl_433 model/id |

Влажность и давление в `.prom` теперь опциональны: ISM-датчики дают влажность
примерно в половине случаев, давление — почти никогда. Отсутствующие метрики
проверки правдоподобия пропускают, из APRS-пакета поля `h`/`b` выпадают
(формат position+weather допускает), обязательны только температура и
свежесть чтения. `vers` поднят до 1.2.

## Что кладём в APRS

Погодный маячок **R2BLN-13** — тот же позывной, что был у BME280-версии:
непрерывность истории на aprs.fi важнее источника. Комментарий называет датчик
(`rtl433 Nexus-TH id=123`), чтобы было видно, что температура — «по округе»,
не своя. Если все датчики замолчали дольше `STALE_AFTER_S`, маячок честно
деградирует до позиции/телеметрии без погоды.

## Грабли

- Сервисные декодеры OpenWebRX+ стартуют только на dial-частотах из bandplan
  внутри полосы активного профиля SDR: без профиля `70cm` (центр 433.5 МГц)
  в scheduler-е HF-донгла конвейер глухой. Клиент, вручную переключивший
  донгл на КВ, глушит ISM-декод до возврата.
- `meteo_last_reading_timestamp_seconds` — время последнего декода опорного
  датчика: датчики с периодом медленнее `STALE_AFTER_S` (300 с) не попадут в
  погоду никогда. Обычно шлют раз в 30–60 с.
